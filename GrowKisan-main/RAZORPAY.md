# Razorpay Payment Integration

How online payments work in KisanFarm using the **Razorpay** payment gateway.

The design follows one golden rule: **the Key Secret never leaves the backend**
and is never committed to Git. The order is created on the server, and every
payment is verified on the server before an order is marked paid — a success
screen in the browser is never trusted on its own.

> This project is a **React (Vite) web app served by Spring Boot**, so it uses
> the Razorpay **web Checkout** (`checkout.js`), not the React Native SDK. The
> security model (server-created order + server-side signature verification) is
> identical.

---

## 1. Which keys you need

| Credential | Where it belongs | Committed to Git? |
|---|---|---|
| `RAZORPAY_KEY_ID` (`rzp_test_...` / `rzp_live_...`) | Backend reads it; also sent to the frontend as the public key | No (supplied via env var) |
| `RAZORPAY_KEY_SECRET` | **Backend only** — used to create orders and verify signatures | **Never** |
| `razorpay_order_id` | Generated by the backend per payment | Not a secret (stored in DB) |

- **Key ID** is public — it's handed to the browser so Checkout can open.
- **Key Secret** stays server-side, in memory only.

Get both from the Razorpay Dashboard → **Account & Settings → API Keys →
Generate Key**. Use **Test Mode** keys first (no real money moves).

---

## 2. Where the keys are configured

The keys are **not** stored in any committed file. They come from
**environment variables** at runtime.

`src/main/resources/application.properties` only references the env vars:

```properties
# provider: mock (default) | stripe | razorpay
kisanfarm.payment.provider=${PAYMENT_PROVIDER:mock}

# Razorpay (only used when provider=razorpay). Set via environment variables.
kisanfarm.payment.razorpay.key-id=${RAZORPAY_KEY_ID:}
kisanfarm.payment.razorpay.key-secret=${RAZORPAY_KEY_SECRET:}
```

`${RAZORPAY_KEY_ID:}` means "read the `RAZORPAY_KEY_ID` environment variable; if
missing, default to empty." So this file is safe to commit — it holds
placeholders, not real values.

> **Anyone who pulls the repo must set these env vars themselves** to use the
> real gateway. See [Running](#5-running-the-app) below. See `.env.example` for
> the full list of variables.

## 3. How a payment works (end to end)

```
Customer taps PAY
      |
      v
[Frontend]  POST /api/checkout  { items, address }
      |
      v
[Backend]   - recomputes the amount from trusted product prices (ignores any
              amount sent by the client)
            - creates a Razorpay ORDER via the Razorpay API (Key ID + Secret)
            - saves order + payment (PENDING) in MySQL
            - returns { orderNumber, amount, provider, providerPaymentId=orderId,
                        clientSecret=public Key ID }
      |
      v
[Frontend]  opens Razorpay Checkout with the order id + public Key ID
            customer pays (UPI / Google Pay / PhonePe / QR / card / netbanking)
            Checkout returns: razorpay_payment_id + razorpay_signature
      |
      v
[Frontend]  POST /api/checkout/confirm { orderNumber, providerPaymentId, signature }
      |
      v
[Backend]   - verifies the HMAC-SHA256 signature using the Key Secret
            - only on success: payment -> SUCCESS, order -> CONFIRMED, stock decremented
            - on failure: payment -> FAILED, order stays PENDING
```

The signature is computed by Razorpay over `order_id | payment_id` with the Key
Secret. The backend recomputes it and compares — this is the authoritative
proof of payment.

## 4. Code map

| Concern | File |
|---|---|
| Razorpay provider (create order + verify signature) | `src/main/java/com/kisanfarm/service/RazorpayPaymentProvider.java` |
| Provider abstraction (mock / stripe / razorpay) | `src/main/java/com/kisanfarm/service/PaymentProvider.java` |
| Checkout orchestration (price calc, order/payment persistence) | `src/main/java/com/kisanfarm/service/OrderService.java` |
| REST endpoints `/api/checkout`, `/api/checkout/confirm` | `src/main/java/com/kisanfarm/controller/CheckoutController.java` |
| Config (reads env vars) | `src/main/resources/application.properties` |
| Payment persistence (`payments` table) | `src/main/java/com/kisanfarm/daoimp/PaymentDaoImpl.java` |
| Loads Razorpay `checkout.js` | `frontend/index.html` |
| Opens Checkout on PAY, confirms server-side | `frontend/src/pages/Checkout.jsx` |
| API calls (`checkout`, `confirmPayment`) | `frontend/src/services/orderService.js` |
| SDK dependency `razorpay-java` | `pom.xml` |

### Key provider snippet

```java
// RazorpayPaymentProvider.java
RazorpayClient client = new RazorpayClient(keyId, keySecret);

// create order
JSONObject options = new JSONObject();
options.put("amount", minorUnitsPaise);   // backend-computed, in paise
options.put("currency", "INR");
options.put("receipt", orderNumber);
Order order = client.orders.create(options);
String razorpayOrderId = order.get("id");

// verify signature (returns true only if it matches)
JSONObject attrs = new JSONObject();
attrs.put("razorpay_order_id", storedOrderId);
attrs.put("razorpay_payment_id", clientPaymentId);
attrs.put("razorpay_signature", clientSignature);
boolean ok = Utils.verifyPaymentSignature(attrs, keySecret);
```

The frontend only ever receives the **public Key ID** (as `clientSecret` in the
checkout response) — never the secret.

## 5. Running the app

### Prerequisites
- Java 21, Maven, Node.js (for building the frontend)
- MySQL running on `localhost:3306` (db `kisanfarm`, user/pass `root`/`root`)

### Build the frontend (outputs into Spring Boot's static folder)
```bash
cd frontend
npm install
npm run build
```

### Start the backend with Razorpay (PowerShell)
```powershell
$env:PAYMENT_PROVIDER = "razorpay"
$env:RAZORPAY_KEY_ID = "rzp_test_xxxxxxxxxxxxxx"
$env:RAZORPAY_KEY_SECRET = "your_test_key_secret"
mvn org.springframework.boot:spring-boot-maven-plugin:3.3.5:run
```

macOS / Linux (bash):
```bash
PAYMENT_PROVIDER=razorpay \
RAZORPAY_KEY_ID=rzp_test_xxxxxxxxxxxxxx \
RAZORPAY_KEY_SECRET=your_test_key_secret \
mvn org.springframework.boot:spring-boot-maven-plugin:3.3.5:run
```

On a correct start you'll see:
```
Razorpay payment provider initialized (TEST mode).
Tomcat started on port 8080 (http)
```

Open **http://localhost:8080**.

> If you set no env vars, the app still runs in **mock** mode (payment succeeds
> instantly, no Razorpay screen). Useful for development without keys.

## 6. Testing (Test Mode)

No real money is ever charged in Test Mode. Use Razorpay's test instruments:

- **UPI (simplest):** on the Checkout screen choose **UPI** and enter VPA
  `success@razorpay` (use `failure@razorpay` to simulate a decline).
- **Card:** a domestic test card, e.g. Mastercard `5267 3181 8797 5449`, any
  future expiry, any CVV.

Notes:
- On a **desktop browser**, UPI appears as a *VPA field + QR*. The tap-to-open
  Google Pay / PhonePe buttons show on a **mobile browser** (open
  `http://<your-PC-IP>:8080` from a phone on the same network).
- UPI/cards behave fully once the Razorpay account is **KYC-approved**; on a
  fresh test account some methods (e.g. international cards) are blocked.

## 7. Going live

1. Complete Razorpay KYC; generate **live** keys (`rzp_live_...`).
2. Relaunch with the live `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` and
   `PAYMENT_PROVIDER=razorpay`. **No code change needed.**
3. Real money will move — test with a small amount and refund from the dashboard.

> **Security:** never commit a real secret. If a secret is ever exposed (e.g.
> pasted somewhere), regenerate the key pair in the dashboard so the exposed
> secret is invalidated.

---

## 8. Why a browser "success" alone isn't trusted

A malicious client could fake a success callback. That's why:
- the **amount** is always recomputed on the server from product prices,
- the **order** is created server-side, and
- the **signature** is verified server-side with the Key Secret before the
  order is marked `CONFIRMED`.

For even stronger guarantees in production, add a Razorpay **webhook** that
confirms `payment.captured` server-to-server (not covered by this build).
